Update 4 (2026-06-04: 11 days after release) (Done with the help of GPT-5.5 (on codex) and GPT-5.5-Thinking (i.e. ChatGPT 5.5) thanks):

Note: following these AI fixes and changes, AI should now be significantly stronger than in previous AdvCiv-SAS 5860 releases

- AI:
	- Surgically fix ingame AI having its first settler produce at ~t90 at normal game speed now require at least 3 cities before bWarPlan can take precedence over the immediate need to early expand (fine if we are cramped and dont want to waste hammers for a settler, but, not fine if we have only our capital) (done using BBAI logging (see BBAI change below))
	- Fix SAS worker AI farm and workshop yield valuation: Use plot/player-adjusted improvement food yields instead of base XML yields in AI_bestCityBuild. This lets in-progress farms credit their actual food gain from irrigation, tech, civics and plot context, and lets State Property correctly make workshops food-neutral. Also stop early food-cost workshops from preempting cottages before Renaissance, while still allowing food-neutral workshops and limited Renaissance+ workshop preparation in high-surplus cities. Addresses player feedback at https://forums.civfanatics.com/threads/advciv-sas-simple-advanced-strategy.699716/post-16956641
	- Fix SAS worker AI irrigation undervaluation: now also weighs the longer-term value of strong non-bonus farms for low-food or hill-heavy cities: they can support food-consuming mines, faster growth, or specialist economies, and the logic is more mindful of preserving useful irrigation paths instead of blindly maximizing immediate cottage/workshop yield. Addresses player feedback at https://forums.civfanatics.com/threads/advciv-sas-simple-advanced-strategy.699716/post-16956641

- Mapscripts
	- Reduce Donut.py grid size a bit in Huge (20,20 -> 19,19; about 10% fewer plots) and higher (SAS24 to SAS48) since they scale on huge, and in Large (16,16 -> 15->15; about 12% fewer plots) worldsizes as it was a bit too big. "I left Standard and below unchanged because the next smaller square size overshoots hard: Standard 13 -> 12: about 15% fewer; Small 10 -> 9: about 19% fewer; Tiny 8 -> 7: about 23% fewer". Related to player feedback at: https://forums.civfanatics.com/threads/advciv-sas-simple-advanced-strategy.699716/post-16956448

- UI:
	- fix + - buttons not being visible and selectable in Espionage Tab when rivals met number is high, and beautify the Tab: Removed redundant and distracting `Weight:`, espionage char icon, and `Cost` text (add a Legend link explaining the row fields), and added a new compact mode with tunable met rivals cap (0 effectively means always use it) so large player counts (e.g., in SAS48 world-size) are visible and selectable. Addresses player feedback at https://forums.civfanatics.com/threads/advciv-sas-simple-advanced-strategy.699716/post-16956448
	- Fix Sevopedia 3D audio preview handling: Resolve ID-backed civ Select/Order 3D sounds to AS3D script names through the DLL helper, then play Sevopedia 3D previews with Play3DSound(script, -1, -1, -1). This replaces the earlier playGeneralSound workaround: that fixed civ Select/Order volume, but returned no handle and let generic AS3D previews persist after rapid navigation or leaving Sevopedia. This keeps normal volume after entering a game while still returning a Destroy3DSound-compatible handle, so Replay/Prev/Next and closing Sevopedia can stop prior 3D previews. Raw AS3D script-browser entries already have script names from Sevopedia's XML parser and now use the same stop-capable playback path.
	- add Sevopedia Media Player music playing notes about some 3D sounds not playing or needing a delay to start: Note 2: some Improvement 3D sounds as of now can play no or the wrong sound. Try to click Play several times to hear the correct sound. Note 3: Ambience 3D can start late; e.g;, dog begins around 6-9 seconds, and horn beings at around 8-13 seconds (They seem not to start right away, e.g., after entering city screen).
	- Fix Info Screen Score Tab's ID column being too small: ID was clipped (e.g., "1." if not upscaled or "1" if upscaled instead of "10" with now enough width). Increase the width of other columns, and take the space from V/M column which is not as important, already large enough, and even if not the info can be viewed in the Scoreboard as well

- No gameplay change:
	- BBAI logging is now XML-tunable: BBAI AI-decision logging can now be enabled/disabled and adjusted through SAS defines, rather than editing and recompiling the DLL as in base AdvCiv. This is deemed valuable not only for modders, but also for users who can now view or generate `BBAI.log` files for review. Note: `LoggingEnabled=1` in `CivilizationIV.ini` is still required for Civ4 to write `BBAI.log`. This allowed for example to surgically identify and fix the root cause of a city not producing its first settler until ~T90 at normal game speed, which is way too late (`bWarPlan` was too aggressively gating settler production; now it only blocks settler production after early expansion has reached enough cities (inefficient at that point, better switch strategy)). Note: BBAI logs can be very long; for broad raw-log diagnosis, we usually give to an external LLM/AI such as ChatGPT the log file, as it is as of now agentic-token-free analysis.
	- Perf opt: BBAI logging guard cleanup: now that BBAI logging is runtime-tunable rather than compile-gated, some older logging-only code paths are guarded more explicitly through the relevant log-level defines. This avoids running logging passes or expensive/unneeded evaluation and formatting of log parameters that ultimately won't be used when that log category is disabled.
	- Fix BUG configobj lookup and old Cleaned several old Python 2-style BUG syntax patterns so modern Python 3 linters/parsers can inspect them while keeping Civ4 Python 2.4 compatibility: these distracted modern Python linters such as ruff and prevented them from finding errors. Removed these parser blockers, such as old comma-exception binding `except Exception, e:` (to the already existing `e = sys.exc_info()[1]` in BugUtil.py pattern) and the old compatibility fallback `True, False = 1, 0` (to an equivalent), which improves code quality. This allowed Ruff to surface and find a real previously hidden bug in BUG /Assets/Python/BUG/configobj.py: `_handle_comment` used undefined `_a_to_u('# ')` instead of the correct `self._a_to_u('# ')`, which we then fixed. See also KI#143.
	- Python source encoding cleanup: fixed Ruff E902 `stream did not contain valid UTF-8` errors in old BUG TechWindow Python files by converting them to UTF-8 in VS Code. UTF-8 is the natural target because most Python files in the mod already use it, and this fixed Ruff parsing while preserving comments and leaving runtime code unchanged. This seems less risky than XML encoding edits so done for these py files.
	- A few other very minor changes unlisted.

Update 3 (2026-06-02: 9 days after release) (Done with the help of GPT-5.5 and GPT-5.5? (not sure which model it was based on its unusual behaviour) (on codex) and GPT-5.5-Thinking (i.e. ChatGPT) thanks):

- Game changes:
	- rebalance and buff the UNIT_ENGLISH_YEOMAN_ARCHER: city defense 10->0, free promotions SENTRY->None, melee_shock modifier 10->30, hill atk/def 10/10->20/20. Rationale (from README_Assets_Rebalancing.md): "Moves England's civ-specific unit from late Rifleman timing to the Crossbowman slot. As of now, 7 strength and +30% vs shock melee gives nearly the same anti-shock-melee value as the generic Crossbowman: 7 x 1.30 = 9.1 > 6 x 1.50 = 9.0. Hills modifiers are lower than the generic Crossbowman's, but the higher base strength still makes 7 x 1.20 = 8.4 stronger than 6 x 1.25 = 7.5 on hills, while the stacked hill + shock-melee value stays equal: 7 x 1.50 = 10.5 == 6 x 1.75 = 10.5 (so not weaker than generic sas crossbowman in these). No Iron, higher base strength, and lower cost make the Yeoman more versatile than the generic Crossbowman; the lower cost also fits the longbow/yeoman historical flavor. This fits England's more defensive/economic early profile while still allowing aggressive use for thematic and strategic variety.". See README_Assets_Rebalancing.md for more civ-specific unit changes rationales.
	- Fix Sevopedia 3D audio previews via DLL reverse lookup: Sevopedia 3D sound previews, notably tested civilization Select/Order sounds, played fine from main menu, but became much quieter after entering a game and stayed quiet even after going back to main menu, until civ4 was restarted. Fix: Add a DLL/Python helper to resolve 3D audio script IDs back to their AS3D script names, then play those previews through playGeneralSound. This keeps the correct sound and normal volume, and may also fix other 3D preview sounds that previously may have failed to play or played incorrectly (would need to check). See KI#141.
	- Fix BTG_Cross Huge and several smaller base sizes being too cramped: Increase BTG_Cross grid dimensions with explicit per-world-size rows (instead of all derived from Huge only), and direct rows make the tuning adjustable.
	- Fix RandomScriptMap.py, Archipelago, and possibly other mapscripts being too small at worldsize huge in AdvCiv-SAS: separate helper logic to Assets/Python/SAS_WorldSizeUtils.py, and playable mapscript in PrivateMaps/SAS_Simple_Flat_Grass.py: Added shared Mapscript-related world-size helpers. Note: done in /Assets/Python/SAS_WorldSizeUtils.py rather than in the /PrivateMaps/ folder as a .py file. This is because such a previous design caused the helper-as-a-playable-mapscript related bug, in AdvCiv-SAS only, of RandomScriptMap and Archipelago, e.g. at Huge world size, being generated far too small (`60 x 44`). After the fix it returned to `120 x 84`, matching base AdvCiv visually at a glance, and not being overly cramped anymore. The same issue may also have affected other map scripts that imported the old helper. The old helper now only keeps the minimal new playable mapscript code, not imported by other mapscripts anymore, in the new SAS_Simple_Flat_Grass: a simple sandbox map with almost all land and mostly flat grass tiles.
	- Adjust the grid size of several map scripts that are too big or too small: Tuned several inherited map scripts after the shared-helper fix made their real Huge scale visible again: RandomScriptMap.py is trimmed slightly and its internal legacy world-size buckets now use `SAS_MAGIC_WORLDSIZE_*` so Arena no longer shifts its start-validation/fractal/terrain tuning; Medium_and_Small.py is enlarged a little from Large onward because lower islets usually are not assigned to players, leaving the upper continent-style area cramped; Pangaea.py now uses AdvCiv-SAS world-size keys so Huge uses the intended Pangaea value instead of a smaller fallback; Big_and_Small.py and Custom_Continents.py are trimmed on larger tiers because Huge tested too large.
	- Fixed Base AdvCiv issue: Military Advisor Map tab debug mode did not draw the full minimap section: In debug mode, the Map tab now draws the full minimap section instead of only the active player's known minimap section: the full map is visible in debug anyway, and this lets the human/debugger locate selected players' units even outside the active player's revealed area. See KI#142.
