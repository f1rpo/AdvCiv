- AI
	- Stack attack order — spend expendables first: stack attacks now prefer bombard/collateral and low-effective-strength/low-XP units first (once the stack commits to attack), preserving elite finishers. Rationale: economically efficient (older/weaker units cost upkeep but scale poorly) and strategically safer (keep high-value units for decisive blows or retreats). Change in CvSelectionGroupAI::AI_getBestGroupAttacker. Toggle via SAS defines for A/B testing. See KI#89.
	- Scrapping update: Exception: Allow scrapping for units that have an `ObsoleteTech`. They are less efficient to keep. - Remove the old anti cheap unit system: the ObsoleteTech one is more efficient and versatile, as well as cleaner and much tighter to do the same. Plus ingame we get even better results it seems (less ancient macemen) at a glance
	- Add scrap tolerance beyond unit support costs: we expect to lose a few units during war; having a few extra units helps us not become weaker than our rivals; overshooting may lead to bankruptcy. Formula: `mult * (era + 1) + add` extra units.
	- Heavily increase the importance of XML Unit Cost (Hammers) (reliable reflection of a unit's overall strength: e.g. A 4 Strength Trebuchet at 80 Hammers Cost is stronger than a 5 Strength Axeman at 35 Hammers) when deciding which unit to scrap first, and reduce the importance of experience: A 0 XP swordsman is more valuable than a 10 XP we will likely never upgrade. Also account for map heaviness (e.g. prioritize scrapping land units on archipelago, or galleys on pangea). Change in CvPlayerAI::AI_disbandValue.

- Game Speeds
	- New Game Speeds: `Slow (1500 turns / 300%)` and `Very Slow (2000 turns / 400%)`, slower than Marathon (1000 turns / 200%); and `Turbo (250 turns / 50%)` and `Nitro (165 turns / 33%)`, faster than Quick (330 turns / 67%), that should provide varied experiences. See full game speed details in the new Sevopedia Speeds category.
	- Clarified and made more outwardly visible the Game Speed information: e.g. `"Normal (500 / 100%)"` bullet; `Epic (750 / 150%)` bullet; `GAME SPEED (50 000 BC - 2105 AD)` header, and clarified other fields.
	- Reordered them in XML from fastest to slowest so they appear in this order in the UI (Main Menu)'s "Play Now" Game Speed section.
	- Fix base AdvCiv `iExtraFreeOutsideUnits` incorrect default bug: Faster-than-Marathon speeds ended up with 100 extra free outside units due to two issues: the `iExtraFreeOutsideUnits` XML tag was missing for those speeds, and the DLL fallback default for that tag was incorrectly set to 100 (Marathon explicitly had 1). Fixed by changing the DLL default from 100 to 0, and by adding the missing `iExtraFreeOutsideUnits` game-speed XML field with a value of 0 so nothing relies on defaults. Also added `iUnitCostPercent` in XML for exhaustiveness (value 100) without changing its DLL default (100) since it was correct. Spotted thanks to the new Sevopedia Game Speed Chart. See: KI#92.

- World Size/Scaling
	- New World Sizes: `SAS24`, `SAS32`, `SAS40`, `SAS48`, bigger than Huge (Recommended for about 24, 32, 40, 48 players). They are modified versions of the XXL World mod's largest maps. Recommended DLL to play these is the 48 Civs DLL that is provided in AdvCiv-SAS. Also a new `Arena` World Size smaller than Tiny. See full World Sizes details in the new Sevopedia W. Sizes category.

- Handicaps
	- `iGPThresholdPercent` (great person) stay constant for the human (AI equivalents scale with handicap).
	- `iBaseGrowthThresholdPercent` (base food required to grow a city): Fixed at 100 on all handicaps. Rationale: In base AdvCiv this value varies by difficulty to add a human growth/expansion penalty (and it can also shift early expansion pacing via settler cost logic tied to the initial growth threshold). Consequence: Removing this scaling makes high handicaps (e.g. Deity) easier for the human player (faster early growth/expansion than base AdvCiv), and makes low handicaps (e.g. Chieftain) harder for the human player (less of an early growth/expansion boost).

- Builds
	- Remove Jungle and Chop Down a Forest builds now use distinct buttons. These are visible both in the Technology Advisor and in Sevopedia Techs' Enables and in the new Sevopedia Builds category panel.

- Eras
	- Add new XML field `<Button>` for eras, to cleanly display them in Sevopedia and ingame without having to hardcode the path.

- Civilizations

- Leaders

- Units (Common)
	- New optional XML field: `ObsoleteTech` for units: if set, this unit can no longer be produced once we have discovered this tech (e.g. Ancient Maceman (`UNIT_WARRIOR`) obsolete at `TECH_BRONZE_WORKING`). This XML field is optional: if not set (`<ObsoleteTech>NONE</ObsoleteTech>`, e.g. for the `UNIT_SETTLER`) or missing entirely (better inter-mod portability), a fallback default of `NONE` is provided anyway, so the unit is never obsolete, meaning no tech discovery will stop allowing to produce it (base AdvCiv/Civ4 behaviour). This new XML field allows to avoid unit clutter in later eras (no more abherrent obsolete units in later eras (e.g. Ancient Maceman produced in Medieval Era; Pikemen in Industrial Era)) being produced or shown in the Production Chooser Bar. AI becomes naturally stronger as a result of these changes. Additionally, this also helps set clean scrapping rules to computationally cheaply detect and remove old units for the AI's military compostion, or further enhancements. See also KI#93.

- Units (Military)
	- Set the ancient maceman's obsolete tech to TECH_ANIMAL_HUSBANDRY for hammer and military efficiency: this unit is useless after the very early game, yet AIs often produce it; humans would have little to gain from stacking them past a certain point fairly early in the game, so make their ObsoleteTech sooner than when we unlock their upgrade (which is as of now the Axeman). By that new tech, we should have archers as a fallback, or should research its tech anyway. Thematically, this is around the time when we domesticate animals, so we no longer have to fight them, if that makes sense. Gameplay wise, we unlock slavery around that time. Most importantly, this tech is on the Hunting path, so it as of now guarantees archers are available.

	- Make the Globe animation in "Play Now" use real scaling instead of demonstrative one, e.g. the new World Size Arena has a ratio to World Size Standard of 0.128, so its model only has 12.8% of the size of the standard-sized globe, and vice versa for sizes bigger than standard. This aims to provide a better representation of real world size differences. See the new Sevopedia W. Sizes Chart category.

- Code/Performance optimizations
	- Heavily refactor and simplify Sevopedia Main so it is much easier to add, reorder, or modify or otherwise maintain categories. See https://github.com/wonderingabout/AdvCiv-SAS/commit/aca192481508a3cac3e8812dc970aebc8675b874
	- Move groupings logic from SevoPediaMain.py to _sevopedia_main_groupings.py + refactor/perf opt: do not re-sort in sevopedia groupings
	- Remove gc and localText as parameters or local variables or such when not relevant in _sevopedia_helpers.py and related files
	- Move Leader AI Personality Panel computation to SevoPediaLeaderAIPValues.py
	- Found-value evaluation now uses `int` end-to-end (CitySiteEvaluator, AIFoundValue, CvPlot cache, SPI, Python callback), not `short`. Why: avoid overflow/underflow and short wraparounds in site scoring; keep the logic the same while improving reliability. Expectation: more robust site values, fewer edge-case penalties/boosts from short overflow; no known negative gameplay change. Performance: `int` is typically at least as fast as short on modern CPUs; no slowdown expected. Tested: autoplay ran fine.
	- Removed the old clunky Base AdvCiv's `CONCEPT_TRAIT` XML clutter. Now using the more efficient `WIDGET_PYTHON` similarly instead.
	- Merge into CvCityAI::SAS_AI_findBestFallbackUnit the common duplicated logic in CvCityAI::AI_chooseUnit and CvCity::doTurn
	- Cache once per session precomputed Sevopedia Traits' Charts and Sevopedia Improvements' Weights (Leaders) Chart on category open before any entry is clicked on. This uses a simplified version of the AI Personality Panel's caching approach.
	- Make paths absolute in .gitignore to fix folders with an identical name being incorrectly ignored; add .gitattributes for more precise archiving.
	- > ~500k characters reduced or moved to Long_Comments/ and still ongoing.
